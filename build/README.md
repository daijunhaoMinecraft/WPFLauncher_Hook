# Build Output

`Mcl.Core.dll` in this directory is generated by the
`Build Mcl.Core` GitHub Actions workflow and committed automatically.

Do not edit or build this file locally. The same DLL is also copied to the
legacy `Mcl.Core/bin/x86/Debug/net48/Mcl.Core.dll` path for older local tooling.
`HookUpdateManager.BuildFilePath` reads the public `build/Mcl.Core.dll` copy.

The workflow:

- reads launcher and third-party dependencies from the private
  `WPFLauncher_Hook_Build` repository;
- builds `Mcl.Core/Mcl.Core.csproj` for `.NET Framework 4.8`, `Release`, `x86`;
- verifies the private dependency hashes;
- updates `build/Mcl.Core.dll` and the compatibility path atomically.

The proprietary launcher and dependency binaries are never committed here.

Native runtime dependencies `ocr.dll`, `OcrProxy.dll`, `wintun.dll`, and
`WmCode.dll` are stored alongside the public build for distribution.

## Workflow Setup

- Private dependency repository:
  `daijunhaoMinecraft/WPFLauncher_Hook_Build`.
- Repository secret: `WPFLAUNCHER_HOOK_BUILD_DEPLOY_KEY`.
- The secret is a read-only SSH deploy key scoped to the private repository.
- The workflow runs on `main` pushes that change production source, tests,
  scripts, or the workflow itself. It can also be started manually.
- The workflow does not upload GitHub Actions artifacts. It commits only the
  public DLL and its legacy compatibility copy.
- Artifact commits reuse the triggering source commit message and append an
  `MCL-SOURCE-COMMIT` marker so the updater can show useful release notes.

## Local Editor Protection

Normal local builds rewrite the compatibility DLL under `Mcl.Core/bin`. Run this
once after cloning to stop IDEs from including that generated change in commits:

```powershell
.\scripts\Protect-BuildArtifacts.ps1
```

Use `-Disable` only when intentionally inspecting or merging the compatibility
artifact update:

```powershell
.\scripts\Protect-BuildArtifacts.ps1 -Disable
```
